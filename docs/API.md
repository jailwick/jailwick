# Local API

The jailwick app talks to a small JSON API (`internal/server`). It runs only on your machine:

- **Desktop app** (`jailwick-app`): served in-process to its window. No network socket is opened.
- **Browser mode** (`jw app --browser [--port N]`): served on `127.0.0.1` only. Opening the printed
  link `/?token=…` sets an HttpOnly, SameSite=Strict cookie; every other request needs that
  cookie. Requests whose `Host` isn't `127.0.0.1`, `localhost` or `::1` are refused (no DNS
  rebinding).

It is the same functionality as the CLI (see [CLI.md](CLI.md)): every endpoint calls the same
internal packages. It is meant for the app; it is not a stable public API yet.

## Conventions

- JSON in and out. Errors: `{"error": "message"}` with `400` (malformed request), `404` (unknown
  project or workspace), `409` (restart or stop refused: sessions are running), `422` (invalid
  configuration), `423` (the project is already starting, restarting or stopping) or `500`.
- `{name}` is a project name. Field names in `config` objects are the YAML keys of the project and
  workspace files (`jw config edit`, `jw workspace edit`).
- Long operations (`up` may build images) answer when they finish. A start or restart keeps going
  if the request is cancelled; meanwhile the project detail's `build` shows its progress.

## Endpoints

### Overview

| Method | Path | Returns |
|---|---|---|
| `GET` | `/api/overview` | `{version, projects[], workspaces[]}` from the configuration alone, so it answers at once: per project `name, dir, workspace, services` (`running`, `sessions` and `busy` come from `/api/live`). |
| `GET` | `/api/live` | What the runtime reports: `{runtime, projects, ops, health}`. `runtime` is `{name, version, platform, arch, urls, error}`; `projects` has an entry `{sessions, busy}` per running project, by name (a missing project is stopped); `ops` the starts, restarts and stops under way by project (the app's and `jw`'s: `starting`, `restarting`, `stopping`, `building`); `health` the projects with something to show besides running or stopped (as `health` in `/api/projects/{name}`). |
| `GET` | `/api/sessions` | Every session in every running sandbox: `[{project, pid, dir, worktree, started, name, state, id, notify, sid, url, internet, chrome}]`, newest first. `notify` is the Claude Code notification channel the session got for its terminal (`iterm2`, `ghostty`, `kitty`, `terminal_bell`, `notifications_disabled`; see `session_notifications`). `sid` is the session's own sandbox (absent for a session in the project's container), `url` reaches its servers (append `:port`), `internet` is `{open, until?}` (no `until`: until closed), `chrome` is set when the session may use Claude in Chrome, `terminal` names the host terminal app it runs in (absent when unknown). |

### Projects

| `POST` | `/api/projects/draft` | `{dir, values?}` | A project being set up: `{dir, steps[], hints[], yaml, problems[]}`. | `POST` | `/api/projects/{name}/down` | `?force=1` to end running sessions | Stops it: containers and networks removed, data and images kept. `409` while sessions run, unless forced. It finishes even if the request is dropped. `{ok}` |
| `POST` | `/api/projects/{name}/stop-sessions` | | Asks every session to end. `{ok}` |
| `POST` | `/api/projects/{name}/terminal` | `{worktree?, command?: "claude" \| "shell" \| "folder", open?, resume?, dir?}` | Opens `jailwick claude` (or `shell`) in the user's terminal app (config `terminal`); `open`: `--open`, a session with the whole internet; `resume` + `dir`: resumes that conversation in its folder (which must be in the project); `folder` + `dir`: a plain terminal in that folder of the project, without jailwick. `{ok}` |
| `POST` | `/api/projects/{name}/run` | `{action: "start" \| "stop", worktree?}` | Starts or stops the project's run command (`run:`) in the background, in the main checkout or a worktree (with its ports and databases): `[{worktree, pid, started, running, port}]`, the runs there are now (also in the project detail's `runs`). |

| `GET` | `/api/projects/{name}/changes?worktree=&file=` | | What the main checkout (no `worktree`) or a worktree changed: `{base?, head, commits[], files[{path, status, added, deleted, binary?}], diff?, diff_cut?}`. | `PUT` | `/api/projects/{name}/sessions/{sid}/internet` | `{minutes}` (1–1440; 0: until closed) | Lets the session reach the whole internet, except the host and private networks; again: a new end. `{open, until?}`. `400` for a bad duration, `404` for an unknown session. |
| `DELETE` | `/api/projects/{name}/sessions/{sid}/internet` | | Puts the session back on the allowlist (restarts its proxy). `{ok}` |
| `POST` | `/api/projects/{name}/sessions/{sid}/show` | | Brings the host terminal the session runs in forward (recorded by `jw` on the session's container as it starts). `{found, app, note}`: `found` is `tab` (its own window and tab: Terminal, iTerm2, WezTerm, kitty with remote control), `app` (the terminal app only; `note` says why) or `""` (nothing: `note` says why). |
| `POST` | `/api/projects/{name}/sessions/{sid}/end` | | Ends the session's Claude (as closing its terminal would; the conversation is kept, the terminal stays open). `{ok}` |
| `POST` | `/api/projects/{name}/worktrees` | `{name, base?}` | Makes a worktree (`base`: the branch or commit a new branch starts from, `HEAD` by default; a branch that exists is used as is) with its slot, database copies, copied files and setup commands, without a session in it. | `GET` | `/api/projects/{name}/worktree?wt=` | | What removing the worktree would take away: `{name, branch, missing?, changed, into, merged, ahead, pushed, sessions}`: files with uncommitted changes, whether the branch is merged into `into` (the main checkout's branch), its commits not there, whether its remote has them all, and the sessions running in it. |
| `DELETE` | `/api/projects/{name}/worktree?wt=` | `?force=1`: with its uncommitted changes; `?branch=merged` (deleted only if merged) or `any` | Stops its app run, removes the folder, its database copies and Redis database, and frees the slot; the branch is kept unless `branch` says otherwise. `{ok}`; `409` while sessions run in it. |
| `GET` | `/api/projects/{name}/worktree/log?wt=` | | The output of a worktree being made, or made with a problem: `{text}`. |
| `DELETE` | `/api/projects/{name}/worktree/job?wt=` | | Forgets a worktree job that ended with a problem. `{ok}` |
| `GET` | `/api/projects/{name}/branches` | | The repo's local branches, the main checkout's first. |
| `GET` | `/api/projects/{name}/logs` | `?service=&tail=300` (max 5000; no service: all) | `{text}` |
| `GET` | `/api/projects/{name}/verify` | | The isolation checks: `[{section, name, ok, info, detail}]`. |
| `GET` | `/api/projects/{name}/ports` | | Listening ports of the project's container and its sessions': `[{port, address, pid, command, where, sid, url}]`. |
| `GET` | `/api/projects/{name}/blocked` | | What its sandboxes were refused, from the project's records (kept through restarts, stops, ended sessions and reinstalls; also while it is stopped): `{hosts[{Host, Count, First, Last, Projects}], discarded[], kept[], by}`. `hosts`, most often first, leaves out those its allowlist covers by now, those it keeps blocked (`kept`, the project's `blocked`) and those discarded (`discarded`: not refused since). `by` maps each host listed to the sessions that asked for it, most recent first: `[{session?, worktree?, name?, count, first, last}]` (no `session`: the project's own container, shells and runs). | `POST` | `/api/projects/{name}/discard` | `{hosts[{host, last}], restore?}` | Clears hosts from the blocked list until the sandbox asks for them again (`last`: the last refusal shown), or with `restore` brings them back. Kept in the project's data. `{ok}` |
| `POST` | `/api/projects/{name}/block` | `{hosts[], unblock?}` | Keeps hosts blocked (`blocked` in the project file): refused as before, no longer listed or notified about; `unblock` stops keeping them. Allowing a host also unblocks it. `{kept[]}`; `422` for a bad host. |
| `GET` | `/api/projects/{name}/build/log?from=` | | The running (or failed) build's output from byte `from` on, to append: `{text, from, size}` (`from` is where it really starts: `0` for a new log, at most the last 512 KB). `404` without a build. |
| `POST` | `/api/projects/{name}/settings/draft` | `{values}` | The project's settings as setup fields with these values: every step of the new-project setup but the first (services and logins, image, toolset, network, worktrees) and its resources (`resources.memory`, `resources.cpus`); the name and the workspace aren't among them. `{dir, steps[], yaml, problems[]}`, like `/api/projects/draft`. |
| `PUT` | `/api/projects/{name}/settings` | `{values}` | Saves them (settings of services it no longer uses are dropped); a restart applies them. `{ok}`; `422` with the problems. |
| `GET` | `/api/projects/{name}/history` | | Saved conversations: `[{id, dir, where, when, prompt, name?, gone, command}]` (`name`: the one given with `/rename`); `command` resumes it in its folder, for any terminal (e.g. `cd ~/code/api && jw claude <id>`); the same in two parts: `folder` (`~/…`) and `run` (`jw claude <id>`). |
| `GET` | `/api/projects/{name}/notes` | | `{text, path}` |
| `PUT` | `/api/projects/{name}/notes` | `{text}` | Saves the notes (read by the next session). `{ok}` |
| `PATCH` | `/api/projects/{name}/claude` | `{login?: "app" \| "project" \| "", chrome?, profiles?[]}` | Changes the project's Claude settings (`claude.login`, `claude.chrome`, `claude.profiles`); fields left out stay, `login: ""` follows the default. ### Network

| Method | Path | Body | Returns |
|---|---|---|---|
| `GET` | `/api/network` | | `{user[], presets[], preset_problems?, projects{name: domains[]}, project_presets{name: presets[]}, blocked[]}`; `presets` is the catalogue, `{name, description, category, hosts[], broad?, docs?, always?}` by category, the user's own last (category `custom`; `preset_problems`: their files that can't be read) (`broad`: why its hosts accept data from anyone); `blocked` entries are `{Host, Count, First, Last, Projects}` from every project's records (as `/api/projects/{name}/blocked` lists them, without discarded ones), most frequent first. |

| `DELETE` | `/api/presets/{name}` | | Removes a preset of yours; `400` while a project uses it. `{ok}` |

### Front end

`GET /` and any path outside `/api/` serve the app (`index.html` for client-side routes).
